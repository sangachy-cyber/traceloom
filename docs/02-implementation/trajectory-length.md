# 轨迹长度设计说明

## 轨迹长度由用户指定

### 1. 设计原则
- **用户控制**：轨迹长度完全由用户通过输入的织样或文件指定
- **灵活性**：支持任意长度的轨迹，从几秒到几小时
- **一致性**：确保生成的轨迹数据长度与用户指定的时长匹配

### 2. 径元结构和时间计算
- 每个径元的 Body 包含 100 个观测点
- 每个观测点对应 0.1 秒的网络状态
- 因此一个径元对应 10 秒的网络轨迹
- 轨迹总长度 = 径元数量 × 10 秒

### 3. 实现方式

在 `Reweaver.generate_trace` 方法中，我们直接使用用户指定的径元序列生成轨迹：

1. 接收用户提供的径元序列
2. 直接拼接径元的主体数据，不添加额外的过渡或填充
3. 轨迹长度由径元序列的长度决定

在 `WeavingEngine._reweave` 和 `WeavingEngine._build_result` 方法中：

1. 根据用户输入的织样计算总持续时间
2. 确保生成的轨迹数据长度与计算的持续时间匹配
3. 不进行任何硬编码的长度限制或填充

### 4. 优势
- **完全可控**：用户可以根据具体需求指定任意长度的轨迹
- **精确匹配**：生成的轨迹长度与用户指定的时长完全一致
- **高效处理**：避免了不必要的截断或填充操作
- **灵活适应**：可以处理从短时间测试到长时间仿真的各种场景

### 5. 使用示例

```python
import traceloom as tl

# 生成20秒的轨迹（2个径元）
tl.reweave(input="s0x2", output="20s_trace.txt")

# 生成60秒的轨迹（6个径元）
tl.reweave(input="s0x3 -> s1x3", output="60s_trace.txt")

# 生成120秒的轨迹（12个径元）
tl.reweave(input="s0x4 -> s1x4 -> s2x4", output="120s_trace.txt")
```

这样可以确保生成的轨迹长度完全符合用户的需求，为网络仿真和测试提供了更大的灵活性。
